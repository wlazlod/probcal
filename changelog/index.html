    Changelog¶

    All notable changes to this project will be documented in this file.

    Format: Keep a Changelog; versioning: SemVer.

    Unreleased¶

    [0.3.1] - 2026-09-05¶

    No breaking changes: every previously accepted input and object behaves identically.

    Added¶

    • Two-column probability-matrix input, core-wide. _validation.validate_scores now accepts an (n, 2) array whose entries lie in [0, 1] and whose rows sum to 1 within 1e-6 absolute tolerance, returning column 1 — the exact shape every predict_proba call in the ecosystem hands back. Every calibrator's fit/predict_proba/point_inverse, LogitOffset, Chain, the whole metric catalog, and probcal.sklearn's probability-input mode inherit the rule from this one shared validator, with a single unified rejection message replacing the old one. Pinned bit-for-bit by tests/test_validation.py (all 14 registered calibrators plus both LogitOffset modes) and by the two-column kinds added to the mirror-check suite.
    • Fittable Chain (supersedes the 0.3.0 note that a chain composes only fitted stages). Chain(stages) now accepts unfitted stages — construction validates only their types and order — and gains Chain.fit(s, y, sample_weight=None), which fits the head calibrator and then each offset in turn on the running calibrated probabilities; every stage is always refit, so composing already-fitted objects is how a stage stays frozen. stages is stored verbatim; calibrator_/offsets_ are now read-only properties, and every reading method raises the standard not-fitted RuntimeError before a fit. get_params/set_params gain stages__i__param nesting (LogitOffset also gained get_params/set_params to support it), and the serialization payload is unchanged — goldens are byte-identical. Both sklearn adapters clone the calibrator prototype via sklearn.base.clone, so SklearnCalibrator(calibrator=Chain([...])) and CalibratedClassifier(calibrator=Chain([...])) now work with an unfitted chain. Tests: tests/test_chain.py, tests/test_sklearn_duck.py, tests/test_sklearn_offset.py.
    • SklearnOffset. probcal.sklearn.SklearnOffset(delta=None, target_mean=None, *, positive_column=1) (TransformerMixin/BaseEstimator): fit(X, y=None, sample_weight=None) fits an inner offset_ (LogitOffset); transform returns the shifted (n, 1) column, predict_proba the (n, 2) matrix, and to_dict delegates to the fitted LogitOffset's payload. Runs the sklearn estimator checks against its own OFFSET_XFAIL_CHECKS inapplicability table, mirrored in the mirror-check suite. Tests: tests/test_sklearn_offset.py. Docs: guide/sklearn.md's new "Stacking an offset" section.
    • positive_column. A keyword-only parameter on SklearnCalibrator and SklearnOffset naming which column of a two-column input is the positive class. At fit, when the estimator also has y (the calibrator, not the offset), a one-shot UserWarning fires if the selected column's event mean is below the non-event mean, naming the flip as the likely fix — probcal warns, it never auto-flips; input="logit" stays single-column, since a logit matrix has no sum rule to check orientation against. n_features_in_ (1 or 2) is recorded at fit and enforced at predict.
    • LogitOffset.fit(y=). fit gains an optional keyword-only y=None, accepted and ignored in both explicit-delta and target-mean modes, giving Chain.fit's sequential fit protocol one call shape across calibrator and offset stages.

    Fixed¶

    • Calibrators and offsets were unusable directly after a predict_proba-shaped pipeline step — a bare (n, 2) matrix from model.predict_proba(X) raised in every fit/predict_proba call across the package, forcing a manual column slice before every calibration call. The two-column input rule above removes that friction end to end; new tests/test_lightgbm.py (importorskip-gated on sklearn/lightgbm; the CI integrations job now installs lightgbm) pins the fix against a real LGBMClassifier.predict_proba matrix flowing through SklearnCalibrator and SklearnOffset in one Pipeline.

    Documentation¶

    • Reader-oriented documentation reorganization. The nav now answers "who is arriving" — Learn (install, how it works, the 20-minute walkthrough), Guide (task-ordered along the calibrate → evaluate → invert/decide → monitor → act → report lifecycle, with the integrations beside it), Concepts (regrouped theory) — and the front page states that lifecycle once, linking each stage to its guide page. No page changed URL. Three assembled guide pages are new: guide/choosing.md (the calibrator catalog, every factual column naming the test that pins it), guide/cutoffs.md (policy PD → raw cutoff → masterscale → recourse), and guide/auditability.md (artifact → what it proves → how to verify it, plus a worked reviewer session). Every Python block in the docs is now executed page by page against a fixed data vocabulary (tests/test_docs_snippets.py, convention in docs/README.md), so snippets rot loudly rather than silently. Figure coverage is complete: every function in probcal.plots has a committed, alt-texted figure on a prose page — the e-process trajectory with its per-grade panel in concepts/monitoring.md and the faceted reliability grid in guide/groups.md were the two gaps. guide/report.md links and shows a full sample validation report (docs/assets/sample_validation_report.html, regenerated by docs/scripts/generate_sample_report.py). tests/test_docs_structure.py holds the structure to all of it: the 0.3.0 sitemap stays a subset of the new one, the front page keeps naming every capability, no plot function loses its figure.
    • guide/sklearn.md: each tier now states its input shape (scores (n,), (n, 1), or a predict_proba matrix (n, 2)), the single-column contract sentence is extended to cover the two-column case, positive_column, and the orientation warning, and a new "Stacking an offset" section covers the two ways to compose an offset — a single Chain step, or a separate SklearnOffset step with its own governance lifecycle (swapped in from apply_recommendation's output without touching the calibrator). guide/monitoring.md gains a "Re-offsetting inside a pipeline" subsection with the matching SklearnOffset replacement snippet. concepts/offset.md gains a paragraph on Chain.fit's sequential fitting: stages fit on the same calibration data, the offset anchoring the calibrator's in-sample output exactly as CalibratedModel.offset_to does — no cross-fitting, no automatic MLE offset.

    [0.3.0] - 2026-08-29¶

    No breaking API changes — the second stability minor on the road to 1.0: every 0.2.0 call and serialized file keeps working, the 0.2.0 goldens are verified unchanged in CI, the one default-behaviour change (CalibrationMonitor.report()'s post-alarm window, see Changed) has the recommendation_window="trailing" escape hatch, and a weighted PlattCalibrator fit — the one case that was ever wrong — now differs from 0.2.0 (see Fixed); every unweighted fit, and hence every default and golden file, is unchanged.

    • Segmented calibration. probcal.SegmentedCalibrator(base=None, *, unseen="global") (new src/probcal/segmented.py, registered and re-exported from probcal): empirical-Bayes shrunken per-segment logit offsets on top of a shared base map. Fits base (default BetaCalibrator(), cloned via the wrapper.py type(base)(**base.get_params()) pattern) on all data as base_, then per segment g an offset-only logistic MLE against base_'s predictions (offset.estimate_offset, catching the single-outcome-class ValueError as delta_hat=0.0, se=inf — fully shrunk); the between-segment heterogeneity variance tau2 is the DerSimonian & Laird (1986) method-of-moments estimator (tau2=0 when fewer than two segments have a finite se), and each segment's shrunk offset is delta_tilde = delta_hat * tau2/(tau2+se**2) — a noisy small segment shrinks toward the base map, a large precise one keeps most of its own estimate, and tau2=0 recovers complete pooling exactly. fit(s, y, sample_weight=None, *, segments=None) and predict_proba(s, *, segments=None) add a keyword-only segments argument on top of the base signature (segments=None is a single segment "__all__" at fit time and the plain base map, delta=0, at predict time — no signature break for the zero-argument protocol calls); an unseen segment label at predict/inverse time is delta=0 (unseen="global", default) or a ValueError (unseen="raise"). interval_inverse/point_inverse gain a keyword-only segment=None and build Chain([base_, LogitOffset(delta=delta_tilde_g)]) for the requested segment; affine_logit_coeffs_ is (a, b+delta_tilde) only for a single fitted segment, else None (no single affine map across segments). Chain has no segments= slot, so Chain([seg, ...]) always predicts through seg's global map — documented as a limitation, not a bug. Fully serializable (_STATE_ATTRS/_state/_set_state, _params_for_dict/_params_from_dict storing an unfitted base as a {class, params} spec since an unfitted calibrator has no to_dict); new golden tests/golden/SegmentedCalibrator.json. Verified by simulation (docs/scripts/segmented_sim.py::recovery, full-size table in concepts/segmented.md, 2000 runs): on a 6-segment scenario with true offsets spread -0.6..+0.6 and sizes 30..3000, mean MSE 0.1242 for empirical Bayes versus 0.2354 (no pooling) and 0.1680 (complete pooling); on an all-zero-spread scenario at n=3000, max|mean delta_tilde| = 0.0003, i.e. shrinkage degrades gracefully to complete pooling. A reduced-size gate runs in CI (tests/test_segmented_sim.py, pytest.mark.slow). New chapter concepts/segmented.md
    • Closing the monitoring loop. CalibrationMonitor.apply_recommendation(target=None) -> AppliedAction (new monitor.AppliedAction, re-exported from probcal.monitor): closes the report-to-action loop for kind="re-offset" — estimates the log-odds shift by maximum likelihood (offset.estimate_offset) on the same window report()'s trailing diagnostics use (_recommendation_window_start, factored out of report() so the two windows can never disagree), composes the fitted LogitOffset onto target (Chain([target.calibrator_, *target.offsets_, offset]) for a Chain, copy.deepcopy(target).offset_to(delta=est.delta) for a CalibratedModel, None for no target — target itself is never mutated), and returns a fresh CalibrationMonitor with the same constructor parameters (new _ctor_params() helper, also used by to_dict) to watch the corrected pipeline — fresh rather than continued because the old e-process is a martingale under the null that the old forecast is calibrated, which no longer holds once the pipeline changes. kind="re-fit"/"none" return no offset, composed target, or fresh monitor — automatic re-fitting stays out of scope by design. AppliedAction carries kind, offset, composed, monitor, the window of batch labels used, and an audit dict of fingerprints and the estimated delta/se; it is itself serializable (to_dict/from_dict/to_json/from_json/fingerprint, nesting offset/composed/monitor as their own envelopes, with a composed CalibratedModel reattached via AppliedAction.from_dict(d, model=...) exactly as CalibratedModel.from_dict itself). mon is never mutated by the call. New section in concepts/monitoring.md
    • Drift-onset localization. CalibrationMonitor drift-onset estimate: each MonitorStep now records log_e_increment, the batch's additive plug-in log-LR contribution (the offset plug-in's bern_log_lr factor plus the shape plug-in's, each 0.0 when its plug-in is the identity) — unlike e_global, a logsumexp mixture that is not additive across batches, this series is purely additive and exists so drift onset can be localized. New monitor._onset.estimate_onset(increments) -> int is a backward-CUSUM argmax (k* = argmax_k sum_{j>=k} increments[j], ties resolving to the latest k) — an estimate, not a change-point test: no type-I control, no confidence set. report() runs it whenever an alarm has fired and exposes the result as the new MonitorReport.onset_label: str | None field, with a matching sentence appended to reasoning; steps loaded from a pre-0.3 payload carry log_e_increment = None (that payload records no increments), and a monitor holding any such step reports onset_label = None, says so in reasoning, and falls back to the "trailing" diagnostic window. Localization accuracy (batches built like docs/scripts/monitor_sim.py's, drift injected at batch 12 of 24 with shift=0.6, 40 seeded runs, tests/test_monitor_onset.py, pytest.mark.slow): median |onset - 12| = 1.0 (gate <= 2). New section in concepts/monitoring.md
    • Per-grade confidence sequences. CalibrationMonitor: each grade in a grade array now also gets its own time-uniform confidence sequence for its own offset — same construction and delta_ci_grid as the portfolio-level delta_ci, restricted to that grade's batch slice with the grade's own predictable plug-in as the alternative — surfaced as the new MonitorStep.grade_delta_ci: dict[str, tuple[float, float] | None] field (empty when no grades are given, and absent on steps loaded from a pre-0.3 payload, since it defaults to {}). This catches a single grade drifting while the portfolio-level offset CS stays put. plots.plot_e_process(report, *, grades_panel=False, ax=None) gains the keyword-only grades_panel: True adds a second axes (ax.figure.add_axes) plotting every grade's CS band across steps below the main plot; the default False call renders pixel-identically to 0.2.0 (tests/test_plots_regression.py). New section in concepts/monitoring.md
    • Per-grade e-test audit. metrics.hl_e_test(y, p, grades, *, mixture_grid=(0.1, 0.25, 0.5, 1.0), sample_weight=None) -> HlEResult (metric catalog 44 → 46 symbols, count updated in docs/api-stability.md): a fixed-sample, one-shot mixture-LR e-value audit per rating grade — for grade g, log E_g = logsumexp over the symmetrized mixture_grid (the same construction CalibrationMonitor's offset e-process uses, monitor._processes.bern_log_lr/logsumexp, with no predictable plug-in since a fixed sample has no strictly-earlier data to learn one from) of Σ_i log LR_i(sigma(logit(p_i) + delta) : p_i), minus log(2 * len(mixture_grid)); the test statistic is the product across grades, e_value = exp(Σ_g log E_g) (a valid e-value: each grade's mixture average has expectation 1 under H0 and grades are disjoint), p_value = min(1, 1 / e_value) by Markov's inequality. Named "mixture-LR grade e-test (safe Hosmer–Lemeshow analogue)": Henzi, Puke, Dimitriadis & Ziegel (2024) is cited in the docstring and concepts/monitoring.md as the paper that motivated a fixed-sample e-value analogue of Hosmer–Lemeshow, explicitly not as the implemented construction. Sample weights enter as exponents on the Bernoulli factors, same convention as the monitor. Verified by simulation (docs/scripts/hl_e_sim.py, full-size table in concepts/monitoring.md, wall time ≈ 19s for 2000 runs): type-I P(e >= 20) = 0.0025 (gate <= 0.0597), P(e >= 100) = 0.0005 (gate <= 0.0144), mean(e) = 0.4334 (gate <= 1 + 3*se); a reduced-size gate runs in CI (tests/test_hl_e_sim.py, pytest.mark.slow). Re-exported from probcal.metrics.grade.
    • Audited offset MLE. probcal.offset.estimate_offset(y, p, *, sample_weight=None) -> OffsetEstimate and probcal.offset.offset_from_estimate(est, p) -> LogitOffset (re-exported from top-level probcal): the offset-only logistic MLE of delta given realized outcomes, with a Fisher-information standard error, as the companion to LogitOffset's policy-driven mode B. The score equation sum(w * (y - sigma(logit(p) + delta))) = 0 is exactly LogitOffset(target_mean=mean_w(y))'s mean-matching condition, so estimate_offset shares its bisection root-finder (new _offset_mle helper) with probcal.monitor._processes.plug_in_delta — the two agree bit-for-bit on the same data; the standard error is 1 / sqrt(sum(w * q * (1 - q))) at the fitted q = sigma(logit(p) + delta). offset_from_estimate builds the same fitted LogitOffset mode A would give for delta=est.delta, so the audited MLE plugs directly into Chain, serialization, and the inverse maps. New section in concepts/offset.md
    • Margin-of-conservatism offsets. probcal.monitor.moc_offset(monitor_or_report, *, level=None) -> LogitOffset and probcal.monitor.moc_offset_from_counts(y, p, *, level=0.9, sample_weight=None) -> LogitOffset (new monitor/_actions.py; re-exported from probcal.monitor and top-level probcal): margin-of-conservatism offsets that turn monitoring evidence into an applied correction. moc_offset reads the upper end of CalibrationMonitor's time-uniform confidence sequence for the current offset (steps[-1].delta_ci[1] by default, or a level recomputed from the monitor's own running _cs_grid/_cs_max state) and returns a fitted LogitOffset(delta=hi) on the last monitored batch — a level requires the live monitor (TypeError for a frozen MonitorReport, which does not retain the running arrays), and an all-nulls-rejected delta_ci/surviving set raises ValueError pointing at delta_ci_grid. moc_offset_from_counts re-anchors p's mean at the one-sided Jeffreys posterior upper quantile of the observed event rate (beta_ppf(level, k + 0.5, n - k + 0.5), the same quantile jeffreys_grade_test/jeffreys_upper_bands use) via LogitOffset's existing mode B — no new numerics. New section in concepts/monitoring.md; monitor.__all__ gains both symbols.
    • Jeffreys masterscale bands. metrics.jeffreys_upper_bands(y, p, grades, *, level=0.9, order=None) -> dict[str, tuple[float, float]] (metric catalog 43 → 44 symbols, count updated in docs/api-stability.md): the per-grade Jeffreys posterior upper bound jeffreys_grade_test already reports as its own-grade display interval (beta_ppf(level, k_i + 0.5, n_i - k_i + 0.5), no cross-grade pooling), packaged as the {grade: (lo, hi)} masterscale band table thresholds.calibrated_bands_to_raw consumes directly — lo_i is the previous grade's hi (0.0 for the best grade), so the bands are contiguous by construction, and a zero-default grade still gets a strictly positive hi from the Jeffreys prior alone. The raw hi sequence is monotonized with _math.pava (weighted isotonic regression, weight = grade size) in the given order (default: grades sorted by mean p, best first), with a UserWarning fired only when PAVA actually changed something. Re-exported from probcal.metrics.grade; new section in concepts/conservatism.md
    • Pluto-Tasche most-prudent PDs. metrics.pluto_tasche(grade_n, grade_d, *, confidence=0.9, grades=None) -> PlutoTascheResult and metrics.pluto_tasche_from_arrays(grades, y, *, order, confidence=0.9, sample_weight=None) (metric catalog 40 → 43 symbols, count updated in docs/api-stability.md): the Pluto & Tasche (2005) one-period most-prudent PD for ordered rating grades — for grade i (best to worst, in the given order), pool its own obligors/defaults with every worse grade's (n*_i = sum(n[i:]), d*_i = sum(d[i:]), the rating-monotonicity assumption doing the work) and take the one-sided Clopper-Pearson upper bound of the pooled rate (_math.beta_ppf(confidence, d*_i + 1, n*_i - d*_i); d* == n* gives 1.0, a pooled n* == 0 raises); pluto_tasche_from_arrays aggregates observation-level (grades, y) into the same counts, weighted when sample_weight is given, and accepts an all-zero y (unlike most probcal metrics) since that is Pluto-Tasche's central use case. pd_upper is replaced by its cumulative maximum best to worst (np.maximum.accumulate, a prudent hull that can only raise a bound, never lower one) to guarantee it stays non-decreasing — a no-op on realistic, already rating-monotone data, PlutoTascheResult.monotonized reports whether it fired. Both functions are re-exported from probcal.metrics.grade, alongside the per-grade backtests they complement. Verified by simulation (docs/scripts/conservative_sim.py, full-size table in the new concepts/conservatism.md): minimum per-grade coverage 0.9225 at confidence 0.9 (gate 0.8866) and 0.9610 at 0.95 (gate 0.9403), 2000 runs; a reduced-size gate runs in CI (tests/test_conservative_sim.py, pytest.mark.slow)

    0.1.3 - 2026-08-16¶

    Fixed¶

    • ENIR (ENIRCalibrator) could exhaust memory well before m=50,000 because path_solutions_ retained every breakpoint's full-length solution (O(m^2) memory); the path solver now retains only the lowest-BIC max_solutions (default 256) breakpoints, bounding memory at any m; a pruning bound that skips provably negligible breakpoints previously crashed on sub-unit total sample_weight (log(total weight) <= 0) — the bound is now disabled in that case instead of raising, regression-tested against a sum-to-1.0 and a sum-below-1.0 case
    • sample_weight was accepted but silently had no effect on e50/e90 and on reliability_summary's internal e90 call — both now honor weights via the new Hazen-position weighted_quantile
    • evaluate's bootstrap silently substituted the point estimate for degenerate single-class i.i.d. resamples, artificially narrowing the reported CI; a degenerate draw is now redrawn (up to 100 times, then RuntimeError) instead of faked
    • CalibratorSelector's name-keyed parsimony table ranked every user-supplied candidate last on a tie regardless of actual complexity; parsimony now reads complexity_rank off the candidate instance, so a user override can win a tie against a built-in method
    • smooth_ece's binned path (default bins=8192) evaluated the smoothed measure on the exact path's 257-point grid, which aliases against the bin lattice: at small bandwidths the probe landed almost entirely between grid nodes, reporting ~1.7e-7 mass against a true total variation of 0.0749 (n=10⁴) — a spurious near-zero reading that always tripped the small-bandwidth guard and fell back to the exact O(n)-per-step computation, so every reported value stayed correct, but at a cost of ~5.7-6.1s/call regardless of n, roughly 3-6x slower than bins=None for 8192 < n ≲ 6×10⁴. The binned path now evaluates the measure natively on its own lattice by direct Gaussian convolution (closed-form total variation when the kernel is isolated, which also makes the early-exit test non-spurious by construction) with one adaptively sized refinement instead of a blind 8x retry; measured n=10⁴: ~5.7s → ~3ms; n=10⁵: 19.7s (exact) → ~10ms (default), same fixed point as exact

    Changed¶

    • ici/e50/e90/emax and reliability_summary fit their LOESS smoother at 512 equal-mass anchors by default instead of at every observation (loess's new grid_size argument, interpolated between anchors, precedent R stats::lowess's delta); measured |Δici| ≈ 1.3e-6 on make_pd_portfolio(n=5000), far below bootstrap CI width; the underlying _loess_fit_sorted core was rewritten from an argpartition r-nearest-neighbor search to a sorted two-pointer window walk, differing from the old core only at exact distance ties (leftmost minimal-width window)
    • smooth_ece smooths a pre-binned (default bins=8192 equal-width logit bins) residual measure instead of the raw per-observation one, cutting each bisection step from 257 x n to a lattice-native evaluation independent of n, with a small-bandwidth guard (sigma* < 8 * bin_width triggers one adaptively sized refinement, bins <- ceil(range / (sigma*/8)), then a silent exact fallback if the guard still trips)
    • ENIRCalibrator.path_solutions_ is now shaped (K, m) over kept_breakpoints_ rather than every breakpoint; path_lambdas_ still records every breakpoint (pre-1.0 attribute-shape change)
    • evaluate's bootstrap resamples negative and positive classes separately by default (stratify=True), conditioning the CI on the observed class balance instead of also capturing base-rate sampling variability; stratify=False restores i.i.d. resampling
    • VennAbersCalibrator predicts from precomputed F0_/F1_ cumulative-sum-diagram sweeps fit once in fit() instead of refitting two PAVA passes per query

    Added¶
